# Mahbub Shop - Entity Relationship Diagrams (ERD)

Because the database schema for Mahbub Shop is large and complex, the Entity Relationship Diagram (ERD) has been broken down into logical modules. These diagrams use standard Crow's Foot notation to represent relationships (`One-to-One`, `One-to-Many`, `Many-to-Many`).

---

## 1. User & Access Control ERD
This diagram outlines how users, staff, and customers are managed along with their roles and groupings.

```mermaid
erDiagram
    USER ||--o{ ADDRESS : manages
    USER }|--o| CUSTOMER_GROUP : belongs_to
    USER }|--o| CUSTOMER_ROLE : assigned
    USER ||--o{ STAFF_ACTIVITY : performs
    USER ||--o{ NOTIFICATION : receives
    USER ||--o{ SESSION : has

    USER {
        String id PK
        String email UK
        String role "ADMIN, MANAGER, STAFF, CUSTOMER"
        String status
    }
    
    ADDRESS {
        String id PK
        String userId FK
        String type
        String street
        String city
    }

    CUSTOMER_GROUP {
        String id PK
        String name UK
        Float discountValue
    }
    
    STAFF_ACTIVITY {
        String id PK
        String userId FK
        String action
        String target
    }
```

## 2. Product Catalog ERD
This diagram shows how products are categorized, defined by attributes, and broken down into variants.

```mermaid
erDiagram
    CATEGORY ||--o{ PRODUCT : contains
    CATEGORY ||--o{ CATEGORY : sub_category
    BRAND ||--o{ PRODUCT : manufactures
    PRODUCT ||--o{ PRODUCT_VARIANT : has
    PRODUCT ||--o{ REVIEW : receives
    ATTRIBUTE ||--|{ ATTRIBUTE_VALUE : defines
    PRODUCT_VARIANT }|--|{ ATTRIBUTE_VALUE : combines

    PRODUCT {
        String id PK
        String slug UK
        String name
        Float basePrice
        Int stock
    }

    PRODUCT_VARIANT {
        String id PK
        String productId FK
        String sku UK
        Float sellingPrice
        Int stock
    }

    CATEGORY {
        String id PK
        String name
        String parentId FK
    }

    ATTRIBUTE {
        String id PK
        String name
    }
```

## 3. Inventory & Supply Chain ERD
This illustrates how products enter the system via suppliers and how stock movements are audited.

```mermaid
erDiagram
    SUPPLIER ||--o{ PURCHASE : supplies
    SUPPLIER ||--o{ SUPPLIER_PAYMENT : receives
    PURCHASE ||--|{ PURCHASE_ITEM : contains
    PURCHASE ||--o{ STOCK_MOVEMENT : triggers
    PRODUCT ||--o{ PURCHASE_ITEM : ordered_as
    PRODUCT ||--o{ STOCK_MOVEMENT : updated_by
    PRODUCT ||--o{ DAMAGE_REPORT : wasted_in

    SUPPLIER {
        String id PK
        String name
        Float dueBalance
    }

    PURCHASE {
        String id PK
        String supplierId FK
        Float totalCost
        String status
    }

    PURCHASE_ITEM {
        String id PK
        String purchaseId FK
        String productId FK
        Int quantity
        Float unitCost
    }

    STOCK_MOVEMENT {
        String id PK
        String productId FK
        String type "IN, OUT, DAMAGE, RETURN"
        Int quantity
        Int newQty
    }

    DAMAGE_REPORT {
        String id PK
        String productId FK
        Int quantity
        Float lossAmount
    }
```

## 4. Sales, Orders & Financials ERD
This diagram tracks the lifecycle of an order, partial due payments, and operational expenses.

```mermaid
erDiagram
    USER ||--o{ ORDER : places
    ORDER ||--|{ ORDER_ITEM : contains
    ORDER ||--o{ ORDER_PAYMENT : paid_via
    ORDER ||--o{ RETURN_REQUEST : refunded_via
    PRODUCT ||--o{ ORDER_ITEM : bought_as
    PRODUCT_VARIANT ||--o{ ORDER_ITEM : bought_as_variant
    EXPENSE_CATEGORY ||--o{ EXPENSE : groups

    ORDER {
        String id PK
        String orderNumber UK
        String source "ONLINE, POS"
        Float totalAmount
        Float dueAmount
        String paymentStatus "UNPAID, PARTIAL, PAID"
    }

    ORDER_ITEM {
        String id PK
        String orderId FK
        String productId FK
        Int quantity
        Float unitPrice
    }

    ORDER_PAYMENT {
        String id PK
        String orderId FK
        Float amount
        String paymentMethod
    }

    EXPENSE {
        String id PK
        String categoryId FK
        String recordedById FK
        Float amount
        String voucherNo
    }
    
    EXPENSE_CATEGORY {
        String id PK
        String name
    }
```

## 5. Marketing & Promotion ERD
This diagram maps out discounts, coupons, and flash sales applied to products and users.

```mermaid
erDiagram
    DISCOUNT ||--o{ PRODUCT_DISCOUNT : applies_to
    PRODUCT ||--o{ PRODUCT_DISCOUNT : discounted_by
    DISCOUNT ||--o{ DISCOUNT_USAGE : tracked_in
    USER ||--o{ DISCOUNT_USAGE : redeems
    FLASH_SALE ||--|{ FLASH_SALE_PRODUCT : features
    PRODUCT ||--o{ FLASH_SALE_PRODUCT : featured_in

    DISCOUNT {
        String id PK
        String code UK
        String type "PERCENTAGE, FLAT"
        Float value
        DateTime startDate
        DateTime endDate
    }

    DISCOUNT_USAGE {
        String id PK
        String userId FK
        String discountId FK
        String orderId FK
        Float discountAmount
    }

    FLASH_SALE {
        String id PK
        String name
        DateTime endDate
        Boolean isActive
    }

    FLASH_SALE_PRODUCT {
        String id PK
        String flashSaleId FK
        String productId FK
        Float salePrice
    }
```
