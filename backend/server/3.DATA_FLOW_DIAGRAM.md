# Mahbub Shop - Data Flow Diagrams (DFD)

This document visualizes the data flow within the Mahbub Shop ecosystem, mapping how data moves between users, internal processes, databases, and external APIs.

---

## 1. Level 0: Context Diagram

This diagram shows the highest-level view of the system, illustrating how external entities interact with the core Mahbub Shop system.

```mermaid
graph TD
    %% External Entities
    Customer((Customer))
    Staff((Admin/Staff))
    PaymentAPI[[Payment Gateways<br/>SSLCommerz, bKash, Stripe]]
    CommAPI[[Communication APIs<br/>Twilio, NodeMailer]]
    AIAPI[[AI Services<br/>Gemini, Groq]]

    %% Core System
    System(((Mahbub Shop<br/>Platform)))

    %% Data Flows
    Customer -- "Searches, Adds to Cart, Places Order" --> System
    Customer -- "Payments" --> System
    System -- "Order Updates, UI Display, Invoices" --> Customer

    Staff -- "Manages Products, Inventory, Expenses" --> System
    Staff -- "Processes POS Sales, Due Collection" --> System
    System -- "Analytics, Reports, Alerts" --> Staff

    System -- "Payment Requests" --> PaymentAPI
    PaymentAPI -- "Payment Success/Failure Webhooks" --> System

    System -- "Email/SMS Payloads" --> CommAPI
    CommAPI -- "Delivery Status" --> System

    System -- "Natural Language Queries / Content Requests" --> AIAPI
    AIAPI -- "Generated AI Responses / Translations" --> System

    classDef core fill:#025da9,stroke:#fff,stroke-width:2px,color:#fff;
    class System core;
```

## 2. Level 1: Core System Processes

This diagram breaks down the main system into its primary sub-systems/processes: Order Management, Inventory, Financials, and Marketing/AI.

```mermaid
graph LR
    %% Entities
    C((Customer))
    S((Admin/Staff))
    DB[(Main Database<br/>MongoDB/Prisma)]

    %% Processes
    P1[1. Order & POS Processing]
    P2[2. Inventory Management]
    P3[3. Finance & Expense]
    P4[4. Marketing & AI Engine]

    %% Flow - Customer
    C -->|Cart, Checkout Data| P1
    C -->|Views/Searches| P4

    %% Flow - Staff
    S -->|POS Sales, Status Updates| P1
    S -->|Add Stock, Log Damage| P2
    S -->|Record Expenses, Collect Due| P3
    S -->|Create Campaigns, Prompt AI| P4

    %% Flow - Interactions
    P1 -->|Order/Payment Details| P3
    P1 -->|Deduct Stock| P2
    P2 -->|Stock Level Alerts| P1
    
    %% Database Reads/Writes
    P1 <-->|Read/Write Orders| DB
    P2 <-->|Read/Write Products/Variants| DB
    P3 <-->|Read/Write Invoices/Expenses| DB
    P4 <-->|Read/Write Customer Data| DB

    classDef process fill:#e8f4f8,stroke:#025da9,stroke-width:2px;
    class P1,P2,P3,P4 process;
```

## 3. Level 2: Order & Due Collection Flow (Detailed)

This diagram focuses specifically on how an order travels through the system from Checkout/POS to Final Completion, including partial payments (Due).

```mermaid
graph TD
    %% Entities
    User((User/Customer))
    Staff((POS Cashier))
    DB[(Database)]

    %% Order Sub-processes
    O1[Cart Validation & Pricing]
    O2[Order Creation]
    O3[Stock Adjustment]
    O4[Payment & Due Processing]
    O5[Invoice & Notification]

    User -->|Checkout Data| O1
    Staff -->|POS Walk-in Data| O1

    O1 -->|Calculates Totals, Tax, Discounts| O2
    O2 -->|Creates Order| DB

    O2 -->|Trigger Stock Reduction| O3
    O3 -->|Update Quantity| DB

    O2 -->|Payment Details| O4
    O4 -->|If Full Payment| O4A[Status: PAID]
    O4 -->|If Partial/Zero| O4B[Status: PARTIAL/UNPAID<br/>DueAmount Logged]
    
    O4A --> DB
    O4B --> DB

    O4A --> O5
    O4B --> O5
    
    O5 -->|Generate PDF Invoice| DB
    O5 -->|Send Email/SMS| Notification((Notifications))

    %% Due Collection
    Staff -->|Logs New Installment| O6[Due Collection System]
    O6 -->|Deducts Due Amount| O4
```

## 4. Level 2: Inventory & Wastage Flow (Detailed)

This shows how inventory levels are manipulated via incoming stock or damages.

```mermaid
graph TD
    %% Entities
    Manager((Inventory Manager))
    DB[(Database)]

    %% Processes
    I1[Add Product/Variant]
    I2[Purchase / Restock]
    I3[Damage / Wastage Report]
    I4[Stock Movement Log]
    
    Manager -->|Setup New SKU| I1
    I1 --> DB

    Manager -->|Add Quantities| I2
    I2 -->|Increments Stock| DB
    I2 -->|Logs Action| I4

    Manager -->|Report Broken Item| I3
    I3 -->|Decrements Stock| DB
    I3 -->|Calculates Loss Amount| DB
    I3 -->|Logs 'DAMAGE' Action| I4

    I4 -->|Maintains Audit Trail| DB
```
